RESUMO DO PROJETO E ROADMAP
FACIL ERP + GFACILERP
================================

DATA DE ATUALIZACAO
-------------------
16/10/2026

VISAO GERAL
-----------
O projeto e composto por dois aplicativos corporativos para Windows,
separados, mas preparados para uma futura integracao segura:

1. FacilERP
   Aplicativo operacional da empresa, voltado para suprimentos, compras,
   fornecedores, notas fiscais, orcamentos, patrimonio e relatorios.

2. GFacilERP
   Aplicativo administrativo, voltado para administradores, usuarios,
   setores, permissoes, aprovacoes, bloqueios e auditoria.

A separacao evita misturar responsabilidades, bancos, permissoes e ciclos de
atualizacao. A integracao futura devera ocorrer por APIs versionadas ou
funcoes server-side, sem liberar acesso direto de terceiros aos bancos.

O QUE O FACILERP FAZ
--------------------
- Controla insumos e produtos utilizados pela empresa.
- Registra o historico de compras.
- Mantem cadastro de fornecedores.
- Registra notas fiscais.
- Apoia o acompanhamento de orcamentos.
- Compara valores e quantidades previstas com valores e quantidades realizadas.
- Controla patrimonio e ativos de TI.
- Exibe informacoes e indicadores em relatorios.
- Possui shell visual corporativo com navegacao entre modulos.
- Possui autenticacao e protecao de sessao no aplicativo.
- Utiliza Supabase para persistencia, autenticacao e politicas de acesso.
- Foi preparado para distribuicao como aplicativo Windows com Tauri.
- Nao deve iniciar com dados demonstrativos ou registros inventados.

O QUE O GFACILERP FAZ
---------------------
- Possui login administrativo separado.
- Valida se o usuario autenticado esta registrado como administrador.
- Permite estruturar usuarios gerenciados e administradores.
- Possui telas de usuarios, auditoria e configuracoes.
- Mantem banco Supabase separado do FacilERP.
- Possui politicas de acesso e RLS especificas para o ambiente
  administrativo.
- Foi projetado para concentrar operacoes administrativas que nao devem
  ficar expostas diretamente no aplicativo operacional.

NOVA IDEIA: LEITURA DE QR CODE
------------------------------
A nova funcionalidade permitira escanear etiquetas e documentos usando a
camera do computador ou dispositivo Windows, reduzindo digitacao manual e
facilitando a operacao diaria.

1. QR CODE PARA PATRIMONIO

- Cada ativo podera possuir uma etiqueta com QR Code.
- O QR Code devera identificar o ativo por um identificador publico e seguro,
  sem conter senha, token ou dados pessoais desnecessarios.
- Ao escanear a etiqueta, o sistema abrira a ficha do patrimonio.
- A ficha podera mostrar nome, tipo, numero de serie mascarado quando
  necessario, status, responsavel e data de aquisicao conforme a permissao
  do usuario.
- A leitura podera facilitar:
  - consulta rapida;
  - conferencia fisica;
  - alteracao de status;
  - alocacao ou devolucao;
  - abertura de manutencao;
  - registro de inventario.
- Acoes de alteracao continuarao exigindo permissao, validacao e confirmacao.

2. QR CODE OU CODIGO DE BARRAS PARA NOTAS FISCAIS

- O sistema podera ler o QR Code impresso no DANFE ou documento fiscal,
  quando o formato fiscal disponibilizar essa informacao.
- A leitura devera preencher ou sugerir campos como chave de acesso, numero,
  serie, data, valor e identificacao do fornecedor.
- O usuario devera revisar os dados antes de salvar.
- O sistema nao devera considerar o QR Code como prova suficiente sem validar
  os dados recebidos e a origem da informacao.
- XML e PDF, quando usados, deverao permanecer em armazenamento privado e
  com acesso controlado.
- A funcionalidade devera tratar QR Code invalido, incompleto, duplicado ou
  incompatível com o formato esperado.

COMO A LEITURA SERA IMPLEMENTADA
--------------------------------
Fase inicial:
- Criar componente reutilizavel de scanner.
- Solicitar permissao de camera somente quando o usuario iniciar a leitura.
- Permitir entrada alternativa por digitacao ou leitor USB.
- Fazer validacao local do conteudo lido.
- Nao salvar automaticamente apos a leitura.
- Exibir uma tela de revisao antes de qualquer persistencia.
- Registrar erros de leitura de forma clara, sem expor informacoes internas.

Fase seguinte:
- Integrar o scanner ao cadastro persistido do modulo Patrimonio.
- Validar geração e impressão de etiquetas em equipamentos reais.
- Integrar o scanner ao fluxo persistido de Notas Fiscais.
- Detectar duplicidade antes de criar uma nota.
- Criar testes com conteudos ficticios de QR Code.
- Validar uso com camera e com leitor USB no Windows.

Fase posterior:
- Inventario por lote de patrimonio.
- Historico de leituras e conferencias.
- Fluxo de divergencia entre etiqueta e cadastro.
- Leitura offline com sincronizacao posterior, se for necessaria.
- Integração segura com validadores ou sistemas fiscais externos, se aplicável.

CRITERIOS DE SEGURANCA PARA QR CODE
-----------------------------------
- Nunca colocar senha, token, service_role ou segredo no QR Code.
- Evitar colocar nome, CPF, e-mail ou outros dados pessoais na etiqueta.
- Preferir um identificador aleatorio ou referencia publica não sensivel.
- Validar formato, tamanho e origem do conteudo lido.
- Nao executar comandos ou URLs arbitrarias vindas do QR Code.
- Nao salvar automaticamente apos escanear.
- Exigir autenticacao e permissao para consultar dados protegidos.
- Exigir confirmacao para alterar status, responsavel ou localizacao.
- Registrar falhas sem armazenar conteudo sensivel desnecessariamente.
- Manter suporte a digitacao manual quando a camera falhar.
